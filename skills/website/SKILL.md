# website

Build production-grade, distinctive Next.js websites the DeployNow way — server-first, layout-stable, deployed on Vercel.

## Overview

The stack is **DeployNow**: JavaScript, Node.js, React, Next.js App Router, Tailwind CSS + DaisyUI, NextAuth, deployed on Vercel. Two principles dominate everything else:

- **Server-first.** Default to React Server Components and SSR. `'use client'`, `useState`, `useEffect` are exceptions you justify, not defaults you reach for. See [reference/server-first.md](reference/server-first.md).
- **Layout stability.** Dynamic content must never displace its siblings, and a broken layout is almost always an *ancestor* constraint — fix the parent, never patch the leaf. See [reference/layout.md](reference/layout.md).

Design is **production-grade and distinctive** — never cookie-cutter. Mobile-first, responsive, ready to ship.

## When to use

- Building a page, component, or feature for a website / web app.
- Naming files or components, or laying out the file structure.
- Deciding server vs client components, data fetching, Suspense.
- Fixing a broken, cramped, or misaligned layout.
- Optimizing images or Web Vitals; handling async errors; deploying to Vercel.

**Not for:** non-web code, native/mobile apps, or generic React questions unrelated to this stack.

## Quick reference

- **Components:** PascalCase, prefixed by type — `ButtonAccount.jsx`, `CardAnalyticsMain.jsx`. Other files: kebab-case. Dirs: kebab-case.
- **Inside a component file:** exported component → subcomponents → helpers → static content.
- **Pure functions:** `function` keyword; concise conditionals without unnecessary braces.
- **Client code:** `'use client'` only for Web API access in small components — never for data fetching or state.
- **Text in JSX:** type real accented chars (á, é, í, ñ, ¿, ¡) directly — a backslash-u unicode escape renders as its literal characters between tags, not as the letter.
- **Builds:** never build locally — let Vercel build; read logs with `vercel inspect`.
- **Mobile tab rows:** una fila de tabs/pills que no cabe → una sola línea con scroll horizontal (`flex-nowrap overflow-x-auto min-w-0` + `shrink-0 whitespace-nowrap` en items), **nunca** `flex-wrap` apilado.

## Common mistakes

- Reaching for `'use client'` + `useState`/`useEffect` to fetch data → use an RSC + server fetch instead.
- Patching a leaf component to fix empty space or cramping → the cap is in an ancestor (page → layout → root → global CSS). Trace upward first.
- Sizing a flex row with `width:fit-content` (+ `max-width:100%`) so it "fills when there are many children" → with `min-width:0` children it collapses to about half the available width, and without the `max-width` it overflows and hides children behind a horizontal scrollbar. Pass the child count as a custom property and use `width: min(100%, calc(...))`. Verify by screenshotting at the target viewport width, not by reading the CSS. See [reference/layout.md](reference/layout.md).
- Committing `public/` while serving media from an external CDN → double-hosting. `public/` goes in `.gitignore` from the first scaffold.
- Using a backslash-u unicode escape in JSX text expecting an accented letter → it renders the raw escape characters; type the real char.
- Apilar tabs/pills con `flex-wrap` en móvil cuando no caben → usa una sola línea con scroll horizontal (`overflow-x-auto` + `min-w-0`). Ver [reference/mobile-design.md](reference/mobile-design.md).
- Adding a third-party pixel/analytics script to a site with a strict CSP without allow-listing its CDN → the loader is blocked *silently* (inline stub queues events that never send). Allow-list `script-src`/`connect-src` and verify the event reaches the vendor dashboard. See [reference/third-party-scripts-csp.md](reference/third-party-scripts-csp.md).
- Mounting `<Analytics />` and calling analytics done → the per-project switch is **off by default** and the component does not flip it; the site records 0 visitors and that history is unrecoverable. Enable it in the same step that takes the site to production. See [reference/vercel-web-analytics.md](reference/vercel-web-analytics.md).
- Ending every `<title>` in the brand's *abbreviation* and writing a purely descriptive `<h1>` → the full brand string then exists in no `<title>` and no `<h1>` on the site, and the short brand search is lost while the long one still works. Keep a `titleBrand` constant separate from `shortName`. See [reference/brand-in-title.md](reference/brand-in-title.md).
- Shipping a local-business site and calling search done at the sitemap → the Google Business Profile listing sits above the organic results, and a listing with **no declared hours** is dropped by the "Open now" filter entirely (reviews are not the gate; hours behave like it). Audit hours, pin, phone, website field and photos. See [reference/google-business-profile.md](reference/google-business-profile.md).
- Placing a page watermark behind the content with `z-index:-1` → every section with an opaque `bg-*` covers it and it looks intermittent. Use one fixed `mix-blend-multiply` layer above the content, and measure its opacity by subtracting two screenshots rather than eyeballing it. See [reference/page-watermark.md](reference/page-watermark.md).
- Rebuilding navigation by hand because a card in a draggable strip "doesn't respond" → the container took `setPointerCapture` on `pointerdown`, which retargets the `click` away from the child `<a>`. Capture only past the drag threshold and the anchor keeps its native click (plus ctrl/middle-click to a new tab). Test with a REAL click — `el.click()` passes with the bug in place. See [reference/draggable-card-strip.md](reference/draggable-card-strip.md).
- Writing a component class in `globals.css` and *also* passing Tailwind color utilities from the JSX → the unlayered class beats the whole `@layer utilities`, so some properties apply and others don't; the typical result is the active state rendering unreadable. One source of truth: the custom class owns every visual state. See [reference/css-cascade-layers-vs-tailwind.md](reference/css-cascade-layers-vs-tailwind.md).
- Pasting a product cut-out onto a generated interior, or generating the interior *with* the product in it → the model redraws the merchandise (a product the client does not sell), and even with the geometry perfect the mismatch in **light** between a warehouse photo and the generated room reads as "pasted" with no prompt fix. Generate the room EMPTY around the product's own photo, and don't composite non-studio-lit photos at all. See [reference/product-photo-compositing.md](reference/product-photo-compositing.md).
- Judging a vectorized line-art logo by `difference / ink pixels` → a perfect trace already spends ~4% on antialias halo, so every candidate looks equally bad. Measure difference *outside* a 1 px contour ring, and count solid cores. Validate the referee against a deliberately broken SVG before trusting it. See [reference/svg-line-art-tracing.md](reference/svg-line-art-tracing.md).
- Dropping favicons straight into a client-logo row, or unifying them with a monochrome treatment → the ones with a color plate baked in read as blocks next to floating drawings, and monochrome turns them into solid discs. Split on corner alpha and normalize both cases into the same round badge. See [reference/client-logo-row.md](reference/client-logo-row.md).
- Omitting an identity field (`author`, `owner`) from a POST because you assume the backend derives it from the token → if it validates the field instead, 100% of requests 400. Sending it costs nothing and works in both worlds. And never hand-type or hardcode a name you compare by equality — accented values have two byte encodings (NFC/NFD) that look identical on screen; pass the session value verbatim. See [reference/api-boundary-contracts.md](reference/api-boundary-contracts.md).
- Deciding in the browser that a server-issued deadline has passed (`data.open && Date.now() < expiresAt`) → the verdict is handed to the least trustworthy clock, and a device running fast locks the control on **every** record at once with no error and no log ("the system is down"). Let the clock only raise a `due` intention that triggers ONE guarded refetch, never let it reopen what the server closed, and assert the skew cases. See [reference/client-clock-vs-server-deadline.md](reference/client-clock-vs-server-deadline.md).
- Passing a Postgres `date` value straight into `new Date()` and formatting it with a `timeZone` → it arrives as midnight UTC and every row renders one day early, with no error anywhere. Slice to 10 chars and anchor to noon UTC, and keep calendar days and instants in separate, differently-named functions. See [reference/calendar-days-vs-instants.md](reference/calendar-days-vs-instants.md).
- Ingesting the "for humans" export of an external system (separate `Fecha` / `Hora inicio` columns) instead of its ISO-with-offset export → a row whose offset was already wrong becomes **permanently** wrong, because the file kept the broken rendering and dropped the zone that proved it (measured: +13 h on a real appointment). Prefer the offset-bearing export, let it win any merge, compute the expected offset for that date, and crash on an unrecognized schema. See [reference/calendar-days-vs-instants.md](reference/calendar-days-vs-instants.md).
- Keeping a UI verdict on a backend boolean after that field changed *meaning* (same name, same type, new truth) → nothing fails and the screen inverts: under the new semantics a healthy row is born `false`, so refetching right after a successful write flashes the failure state on **every** operation. Read the verdict from a status field, draw nothing when the field is `""` (that is absence of instrument, not a state), re-key the cache signature, and route errors on a body `code` rather than on the HTTP status. See [reference/api-boundary-contracts.md](reference/api-boundary-contracts.md).
- Writing a TypeScript type from the written API contract instead of from a measured response → a field the endpoint never returns becomes a compiler-endorsed `undefined` at runtime, which is worse than a crash. Measure first. See [reference/api-boundary-contracts.md](reference/api-boundary-contracts.md).
- Totalling money in JavaScript floats, or collapsing "what customers should pay" and "what actually came in" into one figure → the header stops matching the table underneath it and the panel looks healthier than the business is. Sum in integer cents, send amounts as strings, and keep committed and collected as two numbers. See [reference/money-dashboard.md](reference/money-dashboard.md).
- Treating an explanatory caption on a money screen as decoration → the grouping code can be right while the note under it says something false, and no typecheck, linter, or unit test catches it. Read every caption as an assertion about the code in front of you. See [reference/money-dashboard.md](reference/money-dashboard.md).
- Adding a `no-store` / `revalidate: 0` fetch to `app/layout.jsx` (or to the header/footer it renders) → the layout wraps every page, so **every** route flips from static `○` to dynamic `ƒ`, and a slow API now slows down screens that never used that data. Give that read a `revalidate` matching how often the data really changes, and diff the build's route table before/after. See [reference/static-vs-dynamic-rendering.md](reference/static-vs-dynamic-rendering.md).
- Deduplicating or counting customers by comparing whole phone strings, or normalizing them only at display time → the same subscriber arrives with different country prefixes (some of them corrupt) and every aggregate is quietly wrong. Repair the prefix from the area code, compare by the last 10 digits, and normalize to E.164 at ingest. And do not accept two independent counts that agree as verification — errors of opposite sign cancel. See [reference/phone-normalization-and-dedup.md](reference/phone-normalization-and-dedup.md).
- Confirming DKIM by grepping the mail log for a success string → the happy path is **silent by design**, so the grep returns empty for healthy domains too and the documented check is a guaranteed false negative — whose natural next step is regenerating a key that was fine. Verify with an external receiver, and before trusting any grep as proof, run it against a case you know is healthy. See [reference/domain-email-auth.md](reference/domain-email-auth.md).
- Reporting a lint count on a repo that already had findings, or taking the baseline by linting a copy of the file under `/tmp` → a flat config scopes its rules by globs relative to the config, so the `/tmp` copy is linted with *fewer* rules and the diff invents a regression (measured: 0E for the baseline vs 5E live, actual delta zero). Take the baseline from a `git worktree` at the same relative path, with the same `node_modules` and the same command, and compare the reported **lines**, not the totals. See [reference/lint-delta-baseline.md](reference/lint-delta-baseline.md).
- Debugging "the whole page is shifted / deformed" as a layout bug → one flex row that cannot shrink overflows, and with the default `overflow: visible` that overflow lands in the **document's** scroll width. A screenshot at offset 0 looks fine in both versions; measure `documentElement.scrollWidth > clientWidth` headless instead, then contain the row in its own `overflow-x-auto` scroller with `shrink-0` items. See [reference/overflowing-row-scroll-container.md](reference/overflowing-row-scroll-container.md).
- Styling a disabled control with a *surface* token (`disabled:bg-<surface-sunken>`) → on the screen that uses that surface as its **page** background the control renders at 1.00:1 and disappears, leaving its label reading as stray body copy ("why is that sentence floating there?"). Give the disabled state its own token, off every page surface, and pair it with a body-text label token. See [reference/surface-tokens-and-disabled-state.md](reference/surface-tokens-and-disabled-state.md).
- Fixing a "broken rounded corner" focus ring by giving the inner button the parent's radius → a plain `outline` paints *outside* the border box, and since the child fills the parent exactly, `overflow-hidden` clips the whole ring away: the control ends up with **no** focus indicator, which is an a11y regression disguised as a fix. Hang the ring on the rounded container with `has-[:focus-visible]:outline-*`. See [reference/focus-ring-clipped-by-rounded-parent.md](reference/focus-ring-clipped-by-rounded-parent.md).
- Pushing edits from a checkout with no `node_modules` and letting the remote build be the first thing that can say no → `node --check` cannot parse JSX, so a comment closed early or an unclosed element ships. `new Bun.Transpiler({ loader: 'jsx' })` parses without resolving imports, needs nothing installed, and catches exactly that class. Prove the gate fails on a broken file before trusting it. See [reference/syntax-gate-without-node-modules.md](reference/syntax-gate-without-node-modules.md).
- Trusting `.gitignore` to keep a file out of a deployment → `vercel deploy` uploads the **working directory**, so a gitignored route serves publicly (200) while `git status` stays clean and `git ls-files` never lists it. Only `.vercelignore` excludes it — and while the files remain on disk, deploying **re-publishes** them. See [reference/deploy.md](reference/deploy.md).
- Modelling an optional price or duration as a PocketBase `number` → the field is `NOT NULL DEFAULT 0`, so "never captured" reaches the page as `0`: the card renders **"$0"** and a zero-length duration collides with nothing, letting a scheduler stack bookings. Use a `select` when the values are discrete, or keep the number and enforce "a *visible* record has a price" in a `create` **and** `update` hook. See [reference/pocketbase-schema-and-rules.md](reference/pocketbase-schema-and-rules.md).
- Reading an empty PocketBase collection as proof that its access rule is locked → a denied `list` returns `200` with `items: []` and a denied `view` returns `404`, so empty and gated look identical. Seed a record and confirm superuser sees 1 while anonymous sees 0 — and read the denial signal per collection, since a rules-NULL collection answers `403` where another answers `404`. See [reference/pocketbase-schema-and-rules.md](reference/pocketbase-schema-and-rules.md).
- Locating a public form's own row with `?filter=key="<secret>"` → that read needs `list` open, which a public form must not have, so the id is never obtained and the failure surfaces only on the **second** visit: the retry `POST` hits the unique index and the visitor can answer once but never correct themselves. Burn a deterministic 15-character `id` into the client, `PATCH` it, and fall back to `POST` with that same id on `404`. See [reference/pocketbase-public-editable-form.md](reference/pocketbase-public-editable-form.md).
- Writing a failure message for the team and shipping it to the screen → nothing rejects it, and the reader gets a developer's name to notify, a column name (`visible=false`), or an instruction addressed to a role they themselves are (measured: a guard telling the client to wait for "the client" to confirm). Sweep user-visible strings separately from log strings, remember that staff-only is client-facing when the owner has a staff account, and if the copy promises an automatic retry, implement it. See [reference/user-facing-error-copy.md](reference/user-facing-error-copy.md).
- Attaching the domain without shipping `app/robots.js` + `app/sitemap.js` and handing the operator the Search Console steps → the site is live and invisible. Also: dropping a development `noindex` without setting `alternates: { canonical: '/' }` leaves the `*.vercel.app` preview competing with the real domain. See [reference/indexing-and-search-console.md](reference/indexing-and-search-console.md).
- Typing the sitemap's URLs by hand, or padding it with a build-time `lastModified` plus `priority`/`changeFrequency` → the list starts lying at the first record created from the panel, and dates that all move together on every deploy are the pattern crawlers learn to ignore. Derive it from the same array the routes use and ship bare `<loc>` entries. See [reference/indexing-and-search-console.md](reference/indexing-and-search-console.md).
- Using `robots.txt` `Disallow` to keep a page out of the results, or shipping `metadataBase` and assuming pages now declare a canonical → `Disallow` blocks crawling, not indexing (a linked URL still appears), and `metadataBase` alone emits **no** canonical element. Use per-page `robots: { index: false }`, add `alternates: { canonical: './' }`, and check that both the apex and the `www` don't return 200 independently. See [reference/indexing-and-search-console.md](reference/indexing-and-search-console.md).
